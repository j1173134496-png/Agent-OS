# V0.4 阶段 2：智能填报 Agent 市场接入交付

## 已完成

- `智能填报助手` 使用持久化 Agent ID `agent_smart_submit_v1`。
- 市场发布状态为 `published`，员工角色可使用，禁止员工创建、编辑、分享和配置。
- Agent 固定绑定公司中转站 `立能派中转`。
- 默认模型为已验证的 `gpt-5.5`，允许模型白名单显式记录为 `gpt-5.5`。
- `allow_model_override=false`，用户不能在会话中把 Agent 切换到未验证模型。
- 固定绑定 `submit-flow-skill` 和 `submit-flow` MCP。
- Submit Flow 合同工具必须完整匹配注册表，不能少挂、错挂或增加自由工具。
- 文件入口遵循网页附件流程，仅允许 Submit 所需 PDF，不接受本地路径、URL、Shell、Python、SQL 或任意命令。
- 需要人工复核的任务必须等待用户确认，Agent 不得自行确认。

## 单一事实来源

Agent 行为由 `deployment/agents/smart-submit-v1.json` 描述；`scripts/Sync-AgentOSAgents.ps1` 在同步到 LibreChat 数据库前强制校验模型白名单、MCP、Skill、工具合同和权限。修改 Agent 清单后必须重新执行同步，不能只改数据库。

## 验证命令

仅校验清单和部署依赖：

```powershell
Set-Location K:\Workers\AgentOS
.\scripts\Sync-AgentOSAgents.ps1 -ValidateOnly
```

模型连接验证：

```powershell
.\scripts\Test-AgentOSModelConnection.ps1
```

生产同步需要 Docker 和运行中的 `agentos-mongodb`，执行：

```powershell
.\scripts\Sync-AgentOSAgents.ps1
```

## 阶段 2 验收标准

1. 员工可以从市场打开并开始 `智能填报助手`。
2. Agent 自动使用默认已验证模型，不出现空模型或任意模型下拉项。
3. Agent 能调用 Submit 创建任务、挂载网页附件、查询状态和列出产物。
4. 非 PDF 或本地路径输入被拒绝。
5. `need_review` 状态会展示复核内容并等待确认。
6. 未授权用户不能调用 Submit 工具或下载其他会话产物。
