## Scope completed

- Added a versioned company Agent release manifest with publication status, business version, allowed roles, Skill/MCP/Tool references, risk policy, publisher, and acceptance record.
- Added the native MCP registry and synchronized the Submit Flow Agent to the running MongoDB database.
- Added a dedicated authenticated `/api/agents/marketplace` boundary that returns only published Agents allowed for the current role and forces `VIEW` access.
- Restricted the employee role to native resource use/view/favorite behavior; Agent and Skill creation, editing, sharing, and public sharing remain disabled.
- Hardened Agent favorites so the server re-checks Agent `VIEW` permission before persistence.
- Kept the native `$Skill`/Skill allowlist path and the native image generation menu. The old floating plugin/session path is not active.
- Preserved `agentos_conversation_plugins` for one rollback/audit cycle and recorded the freeze in `deployment/migrations/v0.3.2-legacy-plugin-migration.json`.
- Fixed Marketplace “开始对话” routing so a selected company Agent keeps `agent_id` instead of silently falling back to the default text model spec.
- The platform Agent identity follows LibreChat's required `agent_` persistent-ID contract; the Submit Flow business binding remains `smart-submit-v1` for task compatibility.
