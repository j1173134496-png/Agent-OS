## 1. 文档说明

本文档把现有 PRD 和版本任务书转换成与既有周报相同的“周次 → 工作项 → 状态”展示方式，便于直接用于管理汇报。

文档同时保留两条工作线：

1. **历史业务基础线**：展示第 30—36 周已经形成或正在推进的 Submit Flow、OCR、企业微信、站区报表和 EMS 业务成果。
2. **Agent OS 平台建设线**：展示第 35—44 周从 V0.0.0 到 V0.5.0 的平台建设任务，以及这些历史业务成果如何接入统一 Agent 工作台。

两条线必须分开判断完成状态。历史业务后端已经具备能力，不代表 Agent OS 中对应插件已经完成接入。

## 2. 状态口径

| 状态 | 周报显示 | 判定口径 |
|---|---|---|
| 已完成 | `（完成）` | 交付物存在、测试通过、版本 Gate 已 PASS |
| 待验收 | `（待验收）` | 主要交付物已经形成，仍待评审或 Gate 签署 |
| 进行中 | `（进行中）` | 已经开始执行，但尚未满足完成定义 |
| 待启动 | `（待启动）` | 尚未进入实际实施 |
| 阻塞 | `（阻塞：原因）` | 缺少外部输入、前置版本或关键能力，无法继续 |
| 暂缓 | `（暂缓）` | 已明确不在当前版本实施 |

进度百分比只按任务项数量统计，用于汇报观察，不代替质量判断。版本能否完成只看 Gate。

## 7. 每周汇报固定格式

后续每周只需要复制以下模板并更新状态：

```markdown
- **XX 周（YYYY-MM-DD—YYYY-MM-DD）**

  - 完成事项 1（完成）
  - 完成事项 2（完成）
  - 正在推进事项 3（进行中）
  - 等待外部输入事项 4（阻塞：具体原因）
  - 下周计划事项 5（待启动）

  - 本周版本：V0.X.0
  - 本周 Gate：PASS / FAIL / 待验收
  - 本周交付物：链接或路径
  - 风险与问题：没有则填写“无”
  - 下周目标：一句话描述可见成品
```

### 7.1 周报更新规则

1. 周初把计划任务标为“待启动”。
2. 实际开始后改为“进行中”。
3. 有交付物但未验收时改为“待验收”。
4. 只有 Gate PASS 后才改为“完成”。
5. 阻塞项必须写清责任人、缺少输入和预计解除时间。
6. 延期任务保留在原周，不删除，同时在新周标明“顺延自 XX 周”。
7. 周报中的完成状态必须能够回链到代码、测试报告、截图、运行记录或验收记录。

## 8. V0.5.0 阶段汇报成品

当 V0.5.0 Gate PASS 后，管理层应能够看到以下完整效果：

- 员工打开公司品牌化 Web Agent 工作台并进行普通多轮对话。
- 员工按当前会话添加或移除公司插件；未添加插件时模型看不到业务工具。
- 员工添加“智能填报”插件后，能够上传文件、运行任务、处理人工复核并下载 Excel 和报告。
- 员工添加“EMS Preview”插件后，能够选择站区配置、校验源表、查看逐日差异和下载 Preview 报告。
- 所有业务调用都有 `request_id`、真实状态、错误引用和审计记录。
- 平台不开放 Shell、任意代码执行、任意文件路径、自由 URL 或 EMS 写入能力。
- Submit Flow 和 EMS 继续保持独立业务后端，Agent OS 只负责对话、编排、门禁和结果展示。
