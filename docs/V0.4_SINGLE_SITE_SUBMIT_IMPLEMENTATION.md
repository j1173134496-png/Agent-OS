# AgentOS V0.4：单站区智能填报实施任务书

## 1. 目标与边界

本版本只交付网页端“单站区、单月份、多文件上传、报表输出”闭环。首个站区为 `xinan_high_school`（新安高中部）。用户在 LibreChat 原生智能体市场进入“智能填报助手”，通过对话完成站区/月份确认、附件上传、识别、校验、复核和结果下载。

本版本不做：桌面端本地路径读取、多站区批处理、南科大模板、任意插件标签、模型自行生成业务数字、绕过权限的 Submit 直连。

## 2. 正确的系统分工

* AgentOS/LibreChat：登录、Marketplace、Agent 权限、会话、网页文件上传、对话流、状态卡和受控下载代理。
* Submit Flow：附件归属后的 OCR、站区和报表识别、字段归一化、计费/价格快照、业务校验、统计表/汇总表生成、任务状态和审计。
* 模型：只负责自然语言理解、缺件提示、调用工具和解释结果；不得作为计算或模板事实来源。

链路：`浏览器上传 → AgentOS 文件权限校验 → POST /v1/attachments 暂存 → MCP attach_file 绑定任务 → run_task → get_task/get_review/list_outputs → AgentOS 下载代理`。暂存、绑定和业务识别是三个不同步骤，不能相互冒充。

## 3. 阶段计划与验收标准

### 阶段 A：合同与配置（P0）

1. 固定平台 Agent `agent_smart_submit_v1`（Submit 业务绑定仍为 `smart-submit-v1`）的站区白名单、支持月份格式和必需文件类型。
2. 将 Submit MCP 工具定义、环境变量和 `MCP_REQUIRED_TOOLS` 统一由同步脚本生成，禁止手工漂移。
3. 所有请求携带真实 JWT 用户、租户、Agent、版本和 conversation id；Submit 服务令牌只存在服务端。

验收：未登录、无 Agent USE 权限、跨租户/跨用户/跨会话请求均为 401/403；旧 Agent 不可调用新合同。

### 阶段 B：网页附件桥接（P0）

1. 使用现有 Agent 文件上传接口接收文件，不接受客户端任意本地路径。
2. 服务端重新按用户、租户查询文件，不信任浏览器提供的路径、文件名和大小。调用 Submit 的 HTTP 暂存端点取得真实 `attachment_id`，将映射交给原生 Agent；Agent 使用 MCP `attach_file` 将其绑定到已确认的业务任务。
3. 当前 Submit HTTP 入口只接收 PDF；Excel 是输出格式，本阶段不宣称支持 Excel 材料输入。每个文件最多 20 MiB，每条会话分支最多 10 个去重附件；业务仍须收齐发电单、电费结算单、电量结算单三个角色。最终角色、站区、月份由 Submit 校验。
4. 幂等键由租户、用户、会话、Agent、版本、文件编号、文件名、内容哈希共同生成，使用 Submit 现有持久化幂等记录。后续消息仅重取当前父消息分支的源附件，不能引入旁支附件；过期文件必须重新上传。

验收：上传一组新安高中部样例文件后，Submit 任务能查询到正确附件；另一用户无法复用 attachment id；浏览器不接触 Submit token。

### 阶段 C：对话式任务编排（P0）

1. Agent 先确认站区和月份；仅允许注册表中的 canonical key/alias。
2. 没有当月价格快照时，调用 propose pricing，展示 proposal/hash/来源/缺失字段，必须用户明确确认后再 confirm。
3. 文件不足、格式不符、站区或月份不一致时停止运行并给出可操作提示。
4. `run_task` 使用异步作业语义（提交即返回 task_id，前端轮询 get_task），支持超时、失败重试和幂等键。

验收：成功、缺件、价格待确认、需人工复核、失败重试、重复提交六类场景均有稳定状态，不产生重复任务或静默覆盖。

### 阶段 D：结果与复核体验（P0）

1. 在原生 Agent 消息中展示任务状态、识别摘要、复核字段和错误原因。
2. 复核必须是明确按钮/确认动作，服务端校验 proposal/task 所属用户和会话。
3. `list_outputs` 返回统计表、汇总表等白名单 artifact；新增 AgentOS 下载代理，下载前再次校验权限并审计。

验收：新安高中部样例生成两类目标工作簿，文件名、模板、公式和关键数值与 Submit 基线一致；越权下载返回 403；source_pdf 不作为结果暴露。

### 阶段 E：测试、发布与回滚（P0）

* 单元：adapter 鉴权、绑定、幂等、路径拒绝、价格归属、缺件和错误映射。
* 集成：真实 MCP SDK + 隔离 Submit runtime；不依赖生产数据库或固定本地路径。
* 浏览器回归：Marketplace→Agent→上传→进度→复核→下载全链路。
* 发布记录：baseline commit、配置哈希、镜像 digest、测试报告、已知问题、审批人；Gate 结果必须由机器生成，禁止脚本只匹配文档中的“PASS”。
* 回滚：保留上一镜像 digest 和配置包，演练恢复 Agent manifest、MCP 配置及 Submit runtime。

## 4. 数据与安全要求

任务主键至少包含 tenant/user/conversation/agent/version/site/month；所有 integration link、idempotency 和 artifact 访问记录审计日志。错误消息不得泄漏服务器绝对路径、服务令牌或其他用户数据。历史月份只读取已提交快照，不修改历史模板和运行时数据。

## 5. 实施顺序

先完成 B（附件 adapter 与下载代理）并用测试锁定安全边界，再完成 C/D 的状态和复核体验，最后执行 E 的全量回归和发布。任何阶段未满足验收标准，不得宣称 V0.4 或 V0.3.1 完成。

## 6. 当前已知缺口

实施开始时，Submit MCP 已有 7 个基础工具，但缺少网页附件桥接；Skill 只有文字说明；下载 URL 要求 Submit 服务令牌；`run_task` 为同步调用。历史 Gate/Release Record 的结果漂移需要在最终发布阶段重新核查，而不是沿用旧文档的 PASS。
