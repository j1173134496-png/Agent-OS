## 本轮交付的源码

1. `packages/api/src/submit/bridge.ts`：对真实 `/v1/attachments` 协议上传 PDF，传递服务凭证和完整身份；流式读取有上限，检查 PDF 标识、大小和 SHA-256；拒绝 HTTP 重定向；不把暂存冒充 `attach_file`。
2. `packages/api/src/submit/context.ts`：只查询当前用户的文件，额外检查所有者、租户、保留期限、本地存储路径、类型和整个批次；校验通过后才开始上传。清单不包含服务器路径或令牌。
3. `packages/api/src/submit/native.ts`：使用原有 MCP 环境变量解析器，拒绝用户自建服务替换，检查实际 Agent 绑定与 MCP USE 权限；从当前父消息分支恢复历史附件并合并本次附件。
4. `packages/api/src/submit/upload.ts`：在消息上传阶段保留 Submit 的 PDF 源文件，避免原生通用文本解析链路吞掉源 PDF；其余 Agent、资源和上传流程不变。
5. 两处薄接线：`api/server/services/Endpoints/agents/initialize.js` 与 `api/server/services/Files/process.js`。业务逻辑仍在 TypeScript API 包内。
6. `deployment/skill/submit-flow-skill/SKILL.md`：使用服务端清单里的真实编号，明确新安高中部单站区、单月份、PDF 输入和价格缺失不能假装成功。
7. `packages/api/src/submit/proxy.ts` 与 `api/server/routes/agents/v1.js`：查询任务时再次检查 Agent、会话、用户、租户和单站区边界；只返回可用 `.xlsx` 产物的白名单元数据；下载通过相同边界和 SHA-256 校验。服务端返回固定的通用错误，不泄漏 Submit 内部路径。
8. `packages/data-provider/src/submit.ts`、`client/src/data-provider/Submit` 和 `client/src/components/Chat/Messages/Content/Parts/SubmitTask.tsx`：在原生工具结果下显示加载、处理、人工复核、完成/失败状态，并用图标按钮调用授权下载。没有会话上下文时不发请求。

上述源码路径均相对 `source/librechat-maintained`，部署 Skill 路径相对仓库根目录。

## 复现命令

在 `source/librechat-maintained/packages/api` 的 PowerShell 中执行：

```powershell
$env:SUBMIT_TEST_PROJECT_ROOT = 'K:/Workers/Submit_Flow_Agent'
../../node_modules/.bin/jest.cmd src/submit --runInBand --coverage=false
../../node_modules/.bin/eslint.cmd src/submit --max-warnings 0
../../node_modules/.bin/tsc.cmd --noEmit --pretty false
```

迁移电脑后，把 `SUBMIT_TEST_PROJECT_ROOT` 换成实际 Submit 检出目录；可通过 `SUBMIT_TEST_PYTHON` 指定 Python。未设置项目路径时集成测试会明确 SKIP，不允许将这个结果写成真实联调 PASS。
