# AgentOS V0.3.0 本机运维与验收

## 1. 范围

V0.3.0 在 LibreChat 本机底座上交付可持续扩展的插件框架：插件目录、会话级选择、Skill 加载、工具白名单、Capability Gate、无副作用演示工具、审计引用和图片能力入口。

当前已注册两个插件：

| 插件 | 用途 | 工具 | 状态 |
|---|---|---|---|
| `agentos-demo` | 无副作用能力演示 | `agentos_demo` | 可用 |
| `agentos-image` | 图片生成和编辑 | `image_gen_oai`、`image_edit_oai` | 接入完成，图片接口受中转分组权限限制 |

V0.3.0 不接入 Submit Flow 或 EMS，不开放任意 Shell、Python、SQL、文件路径、URL 或自由命令执行。

## 2. 启动与重建

在 `K:\Workers\AgentOS` 执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Start-AgentOS.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Health-AgentOS.ps1
```

启动脚本会同步 `deployment/librechat.yaml`、确保品牌资源存在并拉取锁定镜像。若远程仓库暂时无法解析已锁定的 LibreChat digest，但本机已有该镜像，可使用本机缓存镜像重建：

```powershell
docker compose --project-name agentos --env-file .env -f deployment\compose.yaml up -d --force-recreate
```

服务地址：<http://localhost:3080>。该 Compose 只发布本机 `127.0.0.1:3080`，MongoDB 数据在 `deployment/data/mongodb/`，停止容器不会删除业务数据。

## 3. 模型和图片能力

本机私密 `.env` 至少应包含以下配置。真实 URL 和 Key 不得写入文档、日志或 Git：

```dotenv
AGENTOS_LLM_MODEL=gpt-5.5
AGENTOS_IMAGE_MODEL=gpt-image-2
AGENTOS_IMAGE_MODELS=gpt-image-1.5,gpt-image-2
```

普通文本对话使用模型选择器中的 `gpt-5.5`。图片模型不会出现在普通文本模型下拉框中，使用路径为：

```text
gpt-5.5 Agent -> AI 能力 -> AI 生图
```

添加“AI 生图”后，Agent 获得两个受控图片工具，默认模型为 `gpt-image-2`，可选 `gpt-image-1.5`。这不是浏览器插件，也不需要额外安装生图扩展；图片能力通过服务端已接入的 Agent 工具调用中转 API。若中转站返回 `Image generation is not enabled for this group`，说明代码链路已经到达中转站，但当前 API 分组没有图片权限。

## 4. 手工验收

1. 打开 <http://localhost:3080> 并登录。
2. 创建新对话，确认底部 `AI 能力 0`。
3. 点击 `AI 能力`，确认能看到“AgentOS 能力演示”和“AI 生图”。
4. 添加“AgentOS 能力演示”，确认计数变为 1，并出现已选标签；再移除，确认回到 0。
5. 添加“AI 生图”，确认显示默认图片模型 `gpt-image-2`。
6. 在新对话中添加一个插件后发送一条普通文本，确认首轮请求成功后插件选择属于该真实会话。
7. 再创建新对话，确认新会话仍为 `AI 能力 0`，不会继承前一个会话的插件。

## 5. 自动化验收

静态 Gate 不需要登录：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\rollback\v0.3.0\Test-AgentOSV03Static.ps1
```

动态 Gate 需要本机测试账号。命令行参数只在本地进程中使用，不要把密码写进脚本或报告：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\rollback\v0.3.0\Test-AgentOSV03.ps1 `
  -Email <test-account-email> `
  -Password <test-account-password>
```

动态 Gate 覆盖：

- 未登录 Catalog 被拒绝。
- 当前用户只能看到授权插件。
- 新会话默认没有 Skill 和工具。
- 插件选择只暴露该插件白名单工具。
- 未选择插件、移除插件和伪造工具调用被拒绝。
- Demo 结果包含 `request_id`、`audit_ref`，并在 MongoDB 审计集合落库。
- Prompt Injection 风格危险字段被拒绝。

运行报告写入 `deployment/runtime/v0.3/`，该目录被 Git 忽略：

- `static-report.json`
- `dynamic-report.json`

V0.3.0 当前验收结果为静态 Gate PASS、动态 Gate PASS。图片模型实际生成仍须等待中转站开通分组权限，再执行 V0.2 模型矩阵。

## 6. 插件扩展约束

新增插件必须同时更新：

- `deployment/rollback/v0.3.0/plugins/catalog.json`：V0.3.0 回滚用 Manifest、角色、风险级别、Skill 和工具白名单。
- `deployment/rollback/v0.3.0/plugins/manifest.schema.json`：V0.3.0 回滚合同 Schema。
- `deployment/rollback/v0.3.0/agentos-runtime/skills/`：V0.3.0 回滚用 Skill。
- `deployment/rollback/v0.3.0/agentos-runtime/pluginRouter.js`：V0.3.0 回滚用受控路由。
- `scripts/rollback/v0.3.0/Test-AgentOSV03Static.ps1` 和动态测试：V0.3.0 历史目录、门禁和越权断言。

服务端必须以 Catalog 和 Capability Gate 为最终权限来源。前端隐藏按钮不是安全控制；客户端传入的工具列表、插件 ID 和危险字段都必须在服务端重新校验。

## 7. 日常检查与停止

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Status-AgentOS.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Logs-AgentOS.ps1 -Service api
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Stop-AgentOS.ps1
```

停止服务不会删除 MongoDB、上传目录或日志目录。不要使用递归删除清理部署目录；任何数据清理都必须单独确认。
