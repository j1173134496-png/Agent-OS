# AgentOS V0.2.0 本机运维与手工验收

## 1. 范围

V0.2.0 在 LibreChat 本机底座上交付公司品牌化登录页、中文界面、服务端自定义端点配置和本机运行验收脚本。

真实模型能力必须通过公司中转 API 验证。系统只把文本模型放入聊天模型选择器；图片模型通过 Agent 的图片工具使用，避免把图片模型误当成聊天模型调用。

运行前提：

- Windows 11。
- Docker Desktop，Linux containers 模式。
- Docker Desktop 已启动，Docker CLI 可用。
- 当前机器使用 amd64/x86_64。

## 2. 启动

在 `K:\Workers\AgentOS` 执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Start-AgentOS.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Health-AgentOS.ps1
```

启动脚本会同步 `deployment/librechat.yaml`，重新创建 API 容器，并只发布本机 `localhost:3080`。

然后打开 <http://localhost:3080>。本机注册默认开启，首次注册的账号密码由操作者自行设置；项目没有固定的默认登录密码。当前已有账号也只能使用注册时设置的密码登录，密码不会从项目文件恢复。

## 3. 配置公司中转 API

只在本机私密 `.env` 中设置以下字段，不要写入 README、Release Record、日志或 Git：

```dotenv
AGENTOS_LLM_BASE_URL=https://relay.example/v1
AGENTOS_LLM_API_KEY=<private-value>
AGENTOS_LLM_MODEL=gpt-5.5
AGENTOS_LLM_MODELS=gpt-5.5,gpt-5.6,gpt-5.6-luna,gpt-5.6-sol,gpt-5.6-terra
AGENTOS_LLM_PROTOCOL=chat_completions
AGENTOS_IMAGE_MODEL=gpt-image-2
AGENTOS_IMAGE_MODELS=gpt-image-1.5,gpt-image-2
AGENTOS_DEFAULT_LOCALE=zh-Hans
ENDPOINTS=custom
```

文本默认模型为 `gpt-5.5`，图片默认模型为 `gpt-image-2`。图片工具也会把 `gpt-image-1.5` 和 `gpt-image-2` 作为受控模型选项传给 Agent；图片生成和编辑请求统一使用同一组中转 URL/API Key。支持的协议值为 `chat_completions` 和 `responses`。能力探针和 20 轮回归脚本会根据该值分别执行对应协议合同；使用 `responses` 时，必须确认中转 API 同时支持 Responses 的流式、函数调用和 JSON Schema 结构。文本模型拉取关闭，服务端使用固定白名单；中转仍建议提供 `/models` 供模型矩阵核对。

配置同步脚本在必需的中转字段任一缺失时生成空的 `custom` 端点，并输出 `BLOCKED`。它不会使用假地址、假密钥或假模型。

## 4. 验证命令

```powershell
# 一次性运行全部 V0.2 Gate
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Test-AgentOSV02Gate.ps1

# 本地服务、品牌、端点隔离和密钥载荷检查
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Test-AgentOSV02Local.ps1

# 代码、配置、浏览器启动载荷和日志的安全检查
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Test-AgentOSV02Security.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Secret-Scan-AgentOS.ps1

# 不联网验证 Chat/Responses 配置合同和密钥占位策略
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Test-AgentOSV02Config.ps1

# 真实中转 API 能力探针
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Test-AgentOSV02Relay.ps1

# 五个文本模型和两个图片模型的真实接口矩阵
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Test-AgentOSV02ModelMatrix.ps1

# 20 轮流式连续对话回归
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Test-AgentOSV02Conversation.ps1
```

报告输出到 `deployment/runtime/v0.2/`：

- `local-report.json`
- `security-report.json`
- `capability-report.json`
- `conversation-regression.json`
- `model-matrix.json`
- `gate-report.json`

`deployment/runtime/` 已被 Git 忽略。报告可以记录 URL、状态、耗时和错误摘要，但不能记录 API Key。

## 5. V0.2 Gate

| 检查项 | 当前状态 | 证据 |
|---|---|---|
| 公司标题、中文登录页和品牌资源 | PASS | `local-report.json`、浏览器页面验收 |
| 服务端自定义端点和默认端点隔离 | PASS | `local-report.json`、`security-report.json` |
| API Key 不进入启动载荷、生成配置和日志 | PASS | `security-report.json` |
| 五个文本模型对话 | PASS | `model-matrix.json` |
| 两个图片模型生成 | BLOCKED 或 PASS | `model-matrix.json`；若中转分组未开通图片权限会记录为 BLOCKED |
| 基础多轮对话 | PASS 或 BLOCKED | `capability-report.json` |
| 流式输出和中断状态 | PASS 或 BLOCKED | `capability-report.json` |
| Tool Calling | BLOCKED | 等待真实中转 API 能力探针 |
| JSON Schema | BLOCKED | 等待真实中转 API 能力探针 |
| 20 轮连续对话 | PASS 或 BLOCKED | `conversation-regression.json` |

只有所有必须项形成 PASS 证据后，Release Record 才能改为 `READY FOR ACCEPTANCE`。Tool Calling 或 JSON Schema 不通过时，V0.4.0 业务插件版本必须保持阻塞。

## 6. 日常操作

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Status-AgentOS.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Logs-AgentOS.ps1 -Service api
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Stop-AgentOS.ps1
```

停止服务不会删除 `deployment/data/mongodb`、上传目录或日志目录。任何删除数据的操作都必须单独确认。

## 7. 安全边界

- 不向员工开放自定义 API Key 或 Base URL 输入。
- 不启动业务插件、MCP Adapter 或 EMS 写入能力。
- 不修改 `Submit_Flow_Agent`、`EMS_Date`，不执行 EMS 写入。
- API Key 只通过服务端私密配置进入 LibreChat；浏览器只接收不含密钥的启动配置。
