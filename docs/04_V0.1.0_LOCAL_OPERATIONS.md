# AgentOS V0.1.0 本机运维与手工验收

## 1. 范围

V0.1.0 只交付 LibreChat 本机基础版：Web 登录、管理员初始化、会话持久化和 Docker 重启恢复。

本版本不要求真实模型、公司中转 API、业务插件或 MCP Adapter 可用。

运行前提：

- Windows 11。
- Docker Desktop，Linux containers 模式。
- Docker Desktop 已启动，Docker CLI 可用。
- 当前机器使用 amd64/x86_64。镜像 digest 按 amd64 锁定。

## 2. 首次启动

在 `K:\Workers\AgentOS` 执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\New-AgentOSEnv.ps1
powershell -ExecutionPolicy Bypass -File .\scripts\Start-AgentOS.ps1
powershell -ExecutionPolicy Bypass -File .\scripts\Health-AgentOS.ps1
```

然后打开 <http://localhost:3080>，完成本机管理员账号注册。

V0.1 默认允许本机首次注册。不要把生成的 `.env` 提交到 Git，也不要将本机服务暴露到局域网。

## 3. 日常操作

```powershell
# 查看容器状态
powershell -ExecutionPolicy Bypass -File .\scripts\Status-AgentOS.ps1

# 查看全部服务最近 200 行日志
powershell -ExecutionPolicy Bypass -File .\scripts\Logs-AgentOS.ps1

# 只查看 Web 服务日志
powershell -ExecutionPolicy Bypass -File .\scripts\Logs-AgentOS.ps1 -Service api

# 停止服务，不删除数据
powershell -ExecutionPolicy Bypass -File .\scripts\Stop-AgentOS.ps1
```

启动脚本使用固定项目名 `agentos`，只发布 `localhost:3080`。V0.1 默认只启动 API 和 MongoDB；Meilisearch、pgvector 和 RAG API 保留在 `supporting` profile，不映射到宿主机端口。

## 4. 持久化位置

| 内容 | 路径 |
|---|---|
| MongoDB | `deployment/data/mongodb` |
| Meilisearch | `deployment/data/meilisearch` |
| pgvector | `deployment/data/pgvector` |
| 上传文件 | `deployment/uploads` |
| Web 日志 | `deployment/logs` |
| UI 图片 | `deployment/images` |
| Skill 目录 | `deployment/skill` |

`docker compose down` 不删除这些目录。任何删除数据的操作必须由操作者单独确认后进行。

## 6. 常见问题

### 端口 3080 被占用

V0.1 的验收端口固定为 3080。先停止占用该端口的本机进程，再重新运行启动脚本；不要修改 Compose 端口来绕过验收口径。

### 容器启动失败

先执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\Status-AgentOS.ps1
powershell -ExecutionPolicy Bypass -File .\scripts\Logs-AgentOS.ps1 -Service api
```

若是镜像拉取失败，确认 Docker Desktop 网络和镜像仓库访问权限；若是数据目录权限问题，确认 Docker Desktop 已授权访问 `K:\Workers\AgentOS`。

### 页面能打开但不能对话

这是 V0.1 的预期边界。模型中转 API 接入属于 V0.2，不在本版本验收范围内。
